Wolff vs. Metropolis: Algorithmic Efficiency in the Critical Regime

Near a second-order phase transition, standard Metropolis-Hastings [1] suffers from critical slowing down: the integrated autocorrelation time \(\tau_{\mathrm{int}}\) [5] grows as \(\tau_{\mathrm{int}} \sim L^z\), with a dynamic critical exponent \(z \approx 2.17\) for the 2D Ising model. Physically, successive spin configurations generated by single-site flips remain highly correlated for many steps because proposed flips within a large correlated domain are overwhelmingly rejected and the system cannot efficiently cross free-energy barriers by small local moves.

The Wolff cluster algorithm [2] largely removes this bottleneck. Rather than proposing a single-spin flip, Wolff grows a cluster from a random seed by probabilistically bonding same-sign nearest neighbours with probability \(P_{\mathrm{add}} = 1 - e^{-2\beta J}\), then flips the entire cluster in one accepted collective move. The bond probability is derived from the Fortuin-Kasteleyn random-cluster representation [3] and guarantees detailed balance without any rejections. The dynamic critical exponent drops to \(z \approx 0.25\), nearly an order of magnitude smaller than Metropolis.

The practical benefit is regime-dependent. Far below \(T_c\) the equilibrium state is a single near-spanning ferromagnetic domain; all grown clusters are system-spanning and flipping them merely reverses the global magnetization without decorrelating the configuration. Far above \(T_c\) the correlation length is short and clusters are vanishingly small, so the BFS overhead dominates. The Wolff advantage is concentrated in the window \(|T - T_c| \lesssim 0.2\,T_c\) where \(\xi\) is large but finite. For a comprehensive review of these methods, see Newman and Barkema [4].

The normalisation problem

A naive comparison of \(\tau_{\mathrm{int}}\) step counts between the two algorithms is misleading because the algorithms do different amounts of physical work per recorded step:

Algorithm

Work per step

Metropolis (checkerboard)

\(L^2\) single-spin flip attempts - one full lattice sweep

Wolff cluster

1 cluster flip of \(\langle C \rangle\) spins - 100% acceptance rate

Counting raw steps treats a Wolff step at \(T \gg T_c\), where a cluster holds only a handful of spins, as equivalent to a Metropolis sweep that touches all \(L^2\) spins. In the disordered phase Wolff then appears to need many more steps than Metropolis, and below \(T_c\), where clusters are nearly system-spanning, a single step does about a sweep of work. A raw step count therefore says nothing about the work each algorithm spends on decorrelation.

The standard fix is to express autocorrelation time in units of one \(L^2\) flip-attempt sweep:

\[\tau^{\mathrm{norm}}_{\mathrm{metro}} = \tau_{\mathrm{steps}} \qquad\qquad \tau^{\mathrm{norm}}_{\mathrm{Wolff}} = \tau_{\mathrm{steps}} \times \frac{\langle C \rangle}{L^2}\]

where \(\langle C \rangle\) is the mean cluster size, measured in a separate pass of up to 300 cluster flips on the equilibrated chain. After normalisation, both algorithms are on the same ruler: how many equivalent full-lattice sweep attempts are needed to decorrelate.

The measurement budget is set in the same unit. Metropolis records one sample per sweep. Wolff records one sample every \(\mathrm{round}(L^2/\langle C \rangle)\) cluster flips, so each Wolff sample also represents about one sweep of flipped spins, and both algorithms receive the same number of samples in sweep units. The stored tau_wolff is converted back to cluster flips (the autocorrelation time in samples times the flips per sample), and the normalisation above turns it into sweeps. Giving both algorithms the same number of raw steps instead would leave Wolff with only a few sweeps of work in the paramagnet, too short a series to resolve its autocorrelation.

This notebook therefore reports two complementary views. The work-normalised \(\tau_{\mathrm{int}}\) makes the decorrelation cost of the two algorithms comparable on one ruler, and the independent-sample rate in inverse seconds sidesteps the unit question altogether, since it is invariant under any rescaling of the update unit and so needs no extra conversion.

Load or compute data

This notebook compares the independent-sample rate and autocorrelation structure of checkerboard Metropolis and Wolff dynamics across temperature. It first searches for precomputed measurements at ../results/ising/wolff_efficiency.npz.

When the cache file is present, the notebook loads median summaries with 16–84% bands across seeds and, when available, per-seed sample arrays for uncertainty-aware analysis. The same plotting code also supports legacy caches that only contain single-value arrays.

When the cache file is absent, the notebook runs a small inline fallback (L=16, 8 temperature points from 1.8 to 3.2, five seed replicas, 500 samples per algorithm) so the workflow remains self-contained. The stored outputs of this notebook come from that fallback. It is useful for validating analysis logic and plotting, but it is intentionally small and should be treated as demo quality: at \(L = 16\) critical slowing down is weak, and the independent-sample rates depend on wall-clock timings that vary between executions.

For publication-quality data, run:

Work normalisation

Raw tau_wolff values count Wolff cluster updates, not full-lattice sweep equivalents. Before comparing dynamics, we convert both algorithms to the same work unit: one \(L^2\)-flip-attempt sweep.

Metropolis (checkerboard) already touches \(L^2\) spins per step, so:

\[\tau^{\mathrm{norm}}_{\mathrm{metro}} = \tau_{\mathrm{metro}}.\]

Wolff touches \(\langle C \rangle\) spins per step, so:

\[\tau^{\mathrm{norm}}_{\mathrm{Wolff}} = \tau_{\mathrm{Wolff}} \times \frac{\langle C \rangle}{L^2}.\]

The cluster fraction \(\langle C \rangle / L^2\) is measured directly from the cluster sizes recorded in a short pass of up to 300 flips (run_with_cluster_sizes) on the equilibrated chain, the same pass that sets the Wolff sample spacing. Both autocorrelation times come from calculate_autocorr, which applies the Madras-Sokal automatic window [5] with window constant 6, cutting the sum at lag \(W = 6\,\tau_{\mathrm{int}}\).

Why ISS itself is unit-invariant

ISS has units of inverse time (independent samples per second):

\[\mathrm{ISS} = \frac{r_u}{\tau_u}.\]

Here \(r_u\) is the update rate (updates per second) and \(\tau_u\) is the autocorrelation time measured in the same update unit \(u\).

If we rescale the update unit by a factor \(a\), then \(r_{u'} = r_u / a\) and \(\tau_{u'} = a\,\tau_u\). Their product is unchanged, so ISS is invariant under this conversion.

So this notebook normalises \(\tau\) explicitly wherever the two algorithms are compared, and leaves ISS numerically untouched, reporting it with uncertainty bands across seed replicas.

Four-panel overview

The four panels show the efficiency comparison across temperature using median values with 16–84% bands over the seed replicas.

Top-left, :math:`tau^{mathrm{norm}}_{mathrm{int}}(T)`: Autocorrelation times in \(L^2\)-sweep equivalents. This is the work-comparable view of decorrelation cost, where critical slowing down of the local update appears as a peak near the transition.

Top-right, :math:`mathrm{ISS}(T)` on a log scale: Independent samples per second with seed-uncertainty bands. ISS is unit-invariant under update-unit rescaling, so values are unchanged by the \(\tau\) normalisation step. The log axis shows where the two curves cross as well as their ratio.

Bottom-left, :math:`langle C rangle / L^2(T)`: Mean cluster-size fraction (with uncertainty). This is the Wolff work-normalisation factor and the physical mechanism behind reduced critical slowing down.

Bottom-right, :math:`chi(T)`: Susceptibility agreement between algorithms (with uncertainty). Agreement confirms both updates sample the same equilibrium distribution; systematic disagreement would indicate a correctness issue.

In the fallback run (\(L = 16\), five seeds, 500 samples per algorithm) the work-normalised Metropolis time rises from 0.92 sweeps at \(T = 1.8\) to a peak of 8.1 sweeps at \(T = 2.4\) and falls back to 1.27 sweeps at \(T = 3.2\). The peak sits above \(T_c = 2.269\) because the pseudo-critical point of a 16 by 16 lattice is shifted to higher temperature; the susceptibility peaks at the same grid point. The Wolff time stays between 0.48 and 1.27 sweeps, so in sweep units the cluster update decorrelates faster at every temperature, by a factor of 1.5 at \(T = 1.8\) and 8.7 at \(T = 2.4\).

The wall-clock rate does not follow \(\tau^{\mathrm{norm}}\) at the edges of the window. Wolff yields more independent samples per second only from \(T = 2.2\) to \(2.6\), by a factor of about two to three (about 3 at \(T = 2.4\)). At \(T = 1.8\) and from \(T = 3.0\) upward Metropolis is ahead, by a factor of about four at \(T = 3.2\), and near \(T = 2.0\) and \(T = 2.8\) the two rates are about equal. Because \(\tau^{\mathrm{norm}}\) favours Wolff everywhere, these losses come from the cost of one sweep-equivalent of work. In the paramagnet a cluster holds 8 to 17 spins (\(\langle C \rangle / L^2\) between 0.03 and 0.07), so one sample takes up to 31 separate cluster flips, each a call into the compiled kernel with its own fixed overhead, while one checkerboard call updates all 256 spins. Deep in the ordered phase a sample costs one cluster flip, but growing a cluster over 92% of the lattice costs more than a checkerboard sweep, and flipping an almost spanning cluster mostly reverses the global magnetisation rather than decorrelating \(|m|\).

The bottom-left panel shows the mechanism behind both effects: the cluster fraction falls from 0.92 at \(T = 1.8\) through 0.65 at \(T = 2.2\) to 0.03 at \(T = 3.2\). In the bottom-right panel the two susceptibility curves agree within the bands at and above the peak (\(\chi \approx 6.4\) for both at \(T = 2.4\)) and at \(T = 1.8\). Just below \(T_c\) the Wolff values are higher: 0.38 against 0.29 at \(T = 2.0\), where the two bands do not overlap, and 2.5 against 1.4 at \(T = 2.2\), where they touch. The gap is a finite-sample bias of the Metropolis estimate, not a disagreement between the samplers. Just below \(T_c\) on a small lattice, \(\mathrm{Var}(|m|)\) is dominated by rare excursions to low \(|m|\), and 500 Metropolis sweeps rarely visit them even though the autocorrelation time of \(|m|\) is only about 2 sweeps. At \(T = 2.0\) and \(L = 16\), the five Metropolis seeds give 0.25 to 0.31 with 500 sweeps and 0.33 to 0.45 with 5 000, and single runs of 200 000 samples give 0.386 (checkerboard), 0.376 (random site), and 0.393 (Wolff), consistent with each other. The cluster update reaches the excursions quickly, which is the efficiency difference this notebook measures.

Across models: Z2 flips versus reflections

Everything above concerns the Ising model. The cluster construction is not tied to a discrete sign flip, and this section measures how the comparison transfers to the XY model and to the discrete six-state clock model.

For the Ising model the Fortuin-Kasteleyn construction bonds aligned neighbours and flips the whole cluster, which is exact because \(s \to -s\) is a symmetry of the Hamiltonian. The planar models have no global sign flip, so Wolff’s embedding [2] replaces it with a reflection. A mirror axis is chosen, each spin’s component \(\sigma_i\) perpendicular to that axis is computed, and neighbours with \(\sigma_i\sigma_j > 0\) are bonded with probability \(P_{\mathrm{add}} = 1 - \exp(-2\beta J\,\sigma_i\sigma_j)\). Reflecting the cluster about the axis leaves the energy of every bond inside it unchanged, so the only energy change sits on the cluster boundary, as for the Ising flip. For the XY model (XYSimulation, kernel o2_wolff_step_numba) the axis is drawn uniformly from the unit circle. For the clock model (DiscreteClockSimulation with \(q = 6\), kernel discrete_clock_wolff_step_numba) it is drawn uniformly from the \(q\) mirror axes of the hexagon at angles \(\pi m / q\), which pass either through a clock state or midway between two. The reflection then maps state \(s\) to \((m - s) \bmod q\), so the update never leaves the discrete state space; Tomita and Okabe restrict the axis in the same way for their cluster updates of the clock model [6]. The local updates differ as well: the clock Metropolis kernel proposes a uniformly random new state, while the XY kernel proposes a rotation by an angle drawn uniformly from \([-0.5, 0.5]\) rad.

The transitions differ in kind. The Ising transition is second order: \(\xi\) diverges as a power law and the slowing down of the local update is concentrated around \(T_c\). The XY transition at \(T_{\mathrm{BKT}} = 0.8933(6)\) [6] is of BKT type: \(\xi\) diverges exponentially as \(T \to T_{\mathrm{BKT}}^+\), and the whole low-temperature phase is critical. The \(q = 6\) clock model has two BKT transitions, at \(T_1 = 0.7014(11)\) and \(T_2 = 0.9008(6)\) [6], with sixfold long-range order below \(T_1\) and an XY-like critical phase between the two. The figure scales each model by one reference temperature: \(T_c\) for Ising, \(T_{\mathrm{BKT}} = 0.893\) for XY, and \(T_2\) for the clock model, for which the code uses 0.92, the earlier estimate of Challa and Landau quoted in [6], about 2% above the Tomita-Okabe value.

Reading the cross-model comparison

Each model is plotted against \(T/T_{\mathrm{ref}}\), so that the reference transitions line up at 1. The data come from the fallback path: one seed, \(L = 16\), five temperatures per model, 400 samples per algorithm, and a single wall-clock timing per point. There are no uncertainty bands, and the four-panel Ising figure above shows that ratios near break-even can move by tens of percent between seeds and executions, so only coarse features are read here.

The right panel shows the mechanism common to the three models. The mean cluster fraction falls from 0.6 to 0.9 of the lattice at the lowest temperatures to a few percent at the highest, and all three curves pass close to 0.35 at \(T/T_{\mathrm{ref}} \approx 1.05\). The Ising curve drops most steeply across its transition.

In the left panel the Ising ratio has the shape of the four-panel figure: Metropolis is ahead at \(0.8\,T_c\) and at \(1.25\) and \(1.4\,T_c\), and Wolff leads only around the transition, by a factor of about 3 at \(1.1\,T_c\). The XY ratio exceeds 1 at all five temperatures and rises monotonically, from about 4 at \(0.5\,T_{\mathrm{BKT}}\) to about 19 at \(1.6\,T_{\mathrm{BKT}}\). The rise into the paramagnet cannot be a critical effect. A likely contribution is the local move itself: the XY Metropolis kernel rotates a spin by at most 0.5 rad per attempt, so the magnetisation direction decorrelates only diffusively, while a reflection can move a spin by any angle. The clock ratio falls below 1 only at the lowest point, \(0.4\,T_2 \approx 0.37\), deep in the ordered phase where the cluster covers about 80% of the lattice. At the other four points it lies between about 2 and 4.5, without a clear peak at either \(T_1/T_2 \approx 0.76\) or \(T_2\).

The ratio folds in the speed of each kernel on this machine as well as the decorrelation per unit work, and at \(L = 16\) the critical slowing down that separates the algorithms near a second-order transition is weak; for Ising it grows as \(L^{2.17}\) for Metropolis against roughly \(L^{0.25}\) for Wolff in sweep units. Comparing peak heights or locating where each curve crosses 1 requires the cached production runs of scripts/ising/wolff_efficiency.py, scripts/xy/wolff_efficiency.py, and scripts/clock/wolff_efficiency.py at larger \(L\) with several seeds.

When to use Wolff

The results above are consistent with the algorithm selection rule documented in AGENTS.md, with the caveat that the fallback run at \(L = 16\) shows only the small-lattice end of it.

Use ``update=’wolff’`` for equilibrium studies near criticality (roughly within 20% of \(T_c\)): finite-size scaling around susceptibility peaks, Binder-cumulant crossing analyses, or critical-exponent measurements. In the fallback run Wolff delivers more independent samples per second from \(T = 2.2\) to \(2.6\), by a factor of about two to three, which reduces the statistical error at fixed wall time, and its work-normalised \(\tau_{\mathrm{int}}\) is lower at every temperature. The advantage grows with lattice size, because the Metropolis autocorrelation time at \(T_c\) grows as \(L^{2.17}\) while the Wolff time in sweep units grows roughly as \(L^{0.25}\).

Use ``update=’checkerboard’`` away from \(T_c\). At \(T = 1.8\) and for \(T \ge 3.0\) Metropolis gives more independent samples per second in the fallback run, by up to a factor of about four at \(T = 3.2\): the cost of many small cluster flips per sweep-equivalent in the paramagnet, or of one near-spanning flip in the ordered phase, outweighs the lower \(\tau^{\mathrm{norm}}\) of the cluster update.

Core comparability rule: never compare raw \(\tau_{\mathrm{int}}\) step counts across algorithms. Always compare \(\tau\) in common work units (here, \(L^2\)-sweep equivalents). ISS can be compared directly in 1/s and is shown with seed uncertainty bands.

For kinetics studies, avoid both checkerboard and Wolff: use update='random' to preserve the intended non-equilibrium Glauber-like dynamics.
