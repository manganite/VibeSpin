# Changelog

All notable changes to VibeSpin are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Version types align with [Conventional Commits](https://www.conventionalcommits.org/): `feat` → Added, `fix` → Fixed, `perf` → Performance, `refactor` → Changed, `docs` → Documentation, `phys` → Physics, `test` → Tests, `chore` → Chores.

**Policy:** Update the `[Unreleased]` section for every commit that changes user-facing behavior (physics, CLI, NPZ schema, public API, or documentation). When cutting a release, move `[Unreleased]` entries to a dated version block.

## [Unreleased]

### Added
- Wolff efficiency comparison for the XY and clock models (`scripts/xy/wolff_efficiency.py`, `scripts/clock/wolff_efficiency.py`), built on the new shared `utils/efficiency_runner.py`. Both models had cluster updates and neither had the measurement that says when to use them. The clock comparison fixes the anisotropy at zero, because the Wolff-Evertz bond construction sees only the exchange term and a comparison at non-zero crystal field would be between two models rather than two algorithms.
- `notebooks/Wolff_Efficiency.ipynb` gains a cross-model section contrasting the Z2 cluster flip with the O(2) reflection, plotting the sampling-rate advantage and the mean cluster fraction against each model's own reduced temperature. The Ising advantage is sharply peaked at T_c, as a diverging power-law correlation length implies, while the XY curve is broad because the entire low-temperature phase is critical.
- `notebooks/Ising_Relaxation_and_Autocorrelation_Analysis.ipynb` gains a section measuring why the ordered-start fallback is enabled for the Ising sweep and not for the vector sweeps. At T=0.1 with L=32 and eight seeds, four Ising and five discrete-clock random starts strand on a plateau below the ordered one while no XY start does: metastable trapping needs a discrete order parameter, since a continuous one lets the domain wall unwind. The section also notes, without acting on it, that a clock sweep run with `--discrete` would trap the way Ising does and does not enable the fallback.
- `scripts/generate_all.py`: one command that regenerates all sixteen cached datasets the notebooks read, reporting each output and its runtime. It runs at production defaults by default and offers `--quick` for a full-pipeline smoke test in about a minute, plus `--only`, `--skip`, `--skip-existing`, `--dry-run`, `--list`, and `--fail-fast`. Until now a fresh checkout could only reach published-quality figures by running fourteen scripts by hand from the pipeline table, and nothing checked that the table was complete. `tests/integration/test_generate_all.py` now holds the two to each other, so a new data-producing script cannot be added to one and forgotten in the other.
- Notebook contract tests (`tests/style/test_notebook_contracts.py`): every `utils`/`models` import in a notebook must resolve, and no notebook may pass positional arguments to a keyword-only project helper. Both checks were validated against the real regressions they are meant to catch. Ruff now lints notebooks as well (the previous `extend-exclude = ["*.ipynb"]` hid them), with prose-layout rules disabled for notebook cells.
- The three temperature-sweep NPZ files now record `size` and `meas_steps`, so a figure can state the lattice it came from. The notebooks print this for the cached path and print their own parameters on the fallback path.
- `--seed` flag on the three `ordering_evolution.py` scripts (previously unseeded, so the figures were not reproducible); default remains unseeded.
- `--n-seeds` accepted as the canonical spelling on the three `ordering_kinetics.py` scripts, aligning with the temperature sweeps; the existing `--seeds` spelling keeps working.
- `--xi-eq-probe`, `--xi-eq-max`, `--xi-eq-steps`, and `--xi-eq-interval` flags on `scripts/ising/coarsening_analysis.py`, replacing four hardcoded equilibrium-measurement parameters.
- New shared `simulate_equilibrium_correlation` helper in `utils/observables.py`, replacing the near-verbatim duplicated per-model workers of the three correlation-comparison scripts. `scripts/ising/correlation_comparison.py` thereby gains two-start convergence equilibration and a `--seed` flag (previously unseeded with fixed-step burn-in, the weakest methodology of its triplet); its `--eq-steps` flag is replaced by `--eq-probe`/`--eq-max`.

- `scripts/clock/compare_discrete_vs_continuous.py`: new `--aniso`, `--seed`, and `--log-file` flags; runs are now reproducible and the anisotropy is no longer hardcoded.
- `scripts/benchmarks/throughput.py`: project-standard logging with `--verbose` and `--log-file` (previously bare `print`).

### Changed
- `run_with_cluster_sizes` moves from `IsingSimulation` to `MonteCarloSimulation`. It only ever used base-class state, and all three models run cluster updates, so having it on Ising alone was an accident of where it was first needed.
- `scripts/ising/correlation_divergence.py` names its entry point `main`, as the other twenty scripts already did; it was the only one calling something else (`run_divergence_analysis`) under `__main__`, and nothing imported the old name.
- The three temperature-sweep scripts now share `utils/sweep_runner.py`, which carries the argument surface, the seed-retry collection loop, the uncertainty bundles, the NPZ schema, and the figure call. The mains shrink from about 380 lines each to roughly 70 and now show only what actually differs between the models: the simulation class, the defaults, the transition overlay, and whether an ordered start is preferred below a critical temperature. A change to the uncertainty schema now reaches all three models at once instead of drifting between them. Verified by running old and new implementations on the same arguments: all 54 NPZ keys and every value are identical for all three models.
- The Wolff-Evertz cluster reflection moves to `models/simulation_base.py` as `o2_wolff_step_numba`, replacing the byte-identical `xy_wolff_step_numba` and `clock_wolff_step_numba`. The bond construction only ever sees the exchange term, so it is the same update for every O(2) model here; the anisotropy caveat it carried for the clock model is stated in the shared docstring, next to the `ClockSimulation` warning that enforces it. Trajectories are unchanged: magnetisation, energy, and the full sequence of cluster sizes match the previous implementation exactly for both models.
- **Production data quality:** the three temperature sweeps raise their defaults to 60 temperature points, 20 000 measurement steps and 5 seed replicas (Ising and XY at L=64, Clock at L=48). The seed count is the decisive change: with the previous single-seed default the cached data carried no between-seed uncertainty, so the hierarchical estimator the schema was built around never ran on production data. Measured cost on four cores is roughly 3 minutes (Ising), 11 minutes (XY) and 16 minutes (Clock).
- **Notebook fallback quality:** fallback parameters raised within an interactive runtime budget, per model rather than uniformly. Ising goes to L=40, 25 temperature points and 10 000 steps (measured: curve roughness 19.9 % to 8.4 %, susceptibility-peak localisation from 0.131 to 0.048 in temperature, 10.6 s). XY and Clock keep L=32 and spend their budget on temperature resolution and statistics instead, because for the vector models a larger lattice increases critical slowing down faster than the statistics improve (Clock roughness 42.4 % to 20.0 %). The correlation fallbacks move from L=40 to L=64 with 6 000 steps.
- The three hand-written correlation fallbacks now call the shared `simulate_equilibrium_correlation`, which falls back to the ordered start when the two-start criterion is not met. Without that fallback a random start stranded by the stuck detector distorted G(r) badly at larger lattices: at L=128 the fitted spin-wave exponent came out as 1.53 against a theoretical 0.064. This is what previously capped those fallbacks at L=40.
- The XY correlation fallback now uses the same temperatures as `scripts/xy/correlation_comparison.py` (0.4 and 1.5) instead of 0.5 and 1.5 times T_BKT. The old values cost no runtime and merely made the surrounding prose, which quotes the spin-wave prediction at T=0.4, wrong on the path that actually executes.
- Notebook `zip()` calls carry `strict=True`, so parallel arrays cannot silently desynchronise.
- Docstring format unified repo-wide to numpydoc: every Parameters/Returns/Raises section across `models/`, `utils/`, and `scripts/` now uses the standard `name : type` entry layout with the type taken from the signature annotation, and prose-only Returns sections carry an explicit return-type line. Rendered API pages now show typed parameter lists uniformly; docstring content is unchanged.
- Logging call style unified to f-strings (the three remaining lazy `%`-style logger calls in `sweep_helpers`, `measure_z`, and `wolff_efficiency` were converted); log output is unchanged.
- `_propagate_entropy_uncertainty_from_cv_errors` replaces its Python backwards loop with a reversed cumulative sum. The NaN-poisoning semantics are preserved exactly (a non-finite segment invalidates its own and all lower-temperature points while higher temperatures stay exact); verified against the previous implementation across finite, partially NaN, all-NaN, unsorted, and edge-size inputs, and covered by a new regression test.
- **Breaking (script path):** `scripts/xy/compare_correlations.py` is renamed to `scripts/xy/correlation_comparison.py`, matching its Ising and Clock siblings; outputs are unchanged. Invocations of the old path must switch to the new name.
- `scripts/ising/coarsening_analysis.py`: the crossover ("bridge") traces now use a seed block offset by 300 from the quench-depth traces, which previously shared identical (temperature, seed) pairs at quench fraction 0.5 and therefore produced identical trajectories; its correlation-length extraction now delegates to the shared interpolating 1/e helper (values shift slightly from grid-snapped to interpolated estimates).
- `utils/__init__` now exports the utilities scripts and notebooks actually consume (equilibration entry points, observables, statistics summarizers, sweep helpers, system infrastructure) instead of a stale eleven-name subset.
- `setup_logging` can attach a file handler on a later call: previously the first call without `log_file` permanently blocked any subsequent call from adding one; console and file handlers are now guarded independently and duplicate file handlers for the same path are skipped.
- `calculate_autocorr` computes the power spectrum as a real array and normalizes only the lags it consumes (up to ``max_lag``) instead of the full series length; `summarize_entropy_observable` builds its result dict through a single helper; the chi/Cv fluctuation formulas live once in `utils.observables.derived_thermo_estimate`, shared by `calculate_thermodynamics` and the derived-observable summarizer.

### Fixed
- **All nine notebooks were unrunnable and now execute end to end.** Three independent causes: five notebooks imported the deleted `utils.analysis` module (pre-existing, from the statistics/observables split); seven notebooks called the equilibration helpers positionally after those became keyword-only; and `Correlation_and_Coarsening` imported `plot_ordering_evolution_snapshots`, which had been removed as unused. The latter two were introduced by this branch: the caller searches behind them covered `scripts/`, `tests/`, `utils/` and `models/` but not `notebooks/`, and no gate executed or linted notebook code. `plot_ordering_evolution_snapshots` is restored (now using the shared 1/e helper rather than its own copy), and the guards described above close the gap.
- `Performance_Benchmarks` caught `ValueError` for `ZeroVarianceAutocorrelationError`, which derives from `RuntimeError`; the handler could never fire on the clock models it was written for.

## [0.1.0] — 2026-03-25

This is the baseline release capturing the full initial development history. The entries below summarize the major milestones grouped by category.

### Added

- **Parallelization:** Granular point-level parallelization — every `(T, seed)` pair is an independent worker task, maximizing CPU utilization even for single-seed sweeps.
- **Uncertainty schema:** Standardized NPZ contract for all temperature-sweep outputs: `<obs>_value`, `<obs>_err`, `<obs>_ci_low`, `<obs>_ci_high`, `<obs>_tau_int`, `<obs>_n_eff`, `<obs>_samples`, plus entropy and `tau_int` asymmetric interval extras.
